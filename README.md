# «Баба Яга против!» — сайт V3

Третья версия демонстрационного сайта настольной игры. В архиве оригинальный логотип и портреты 4 злодеев, два варианта игрового поля, страница правил по предоставленному печатному макету и локальная библиотека вопросов.

## Быстрый запуск

Распакуйте архив, откройте **index.html** в браузере. По кнопке «Библиотека» перейдите на **library.html**. Демонстрационный код: **DEMO** (либо кнопка демоверсии).

В библиотеке выбираются класс (1–4), предмет (злодей), одна из трёх библиотек и **число вопросов на каждый уровень сложности**. Генератор отдельно собирает вопросы для бросков 1–2 (простой), 3–4 (обычный), 5–6 (сложный), перемешивая темы внутри уровня. Нажмите «Печать / PDF»: браузер предложит распечатать листы или сохранить их как PDF; ответы будут на отдельной странице.

На сайте есть добавление вопросов в личный или общественный раздел, а также удаление добавленных вопросов. **Все вопросы, добавленные пользователем, в этой версии хранятся только в localStorage текущего браузера.** Выбор «общественный» не публикует вопрос в Интернете. «Личный» — пока только подпись в локальной демоверсии, **это не защищённый личный кабинет**: другие люди за тем же браузером могут прочесть его данные.

## Файлы

- `index.html` — главная/продажи, карточки злодеев и переключение макетов поля.
- `rules.html` — веб-версия механики из загруженных правил.
- `library.html` — генератор, создание и локальная коллекция вопросов.
- `css/style.css`, `css/v3.css` — стили.
- `js/questions.js` — **демонстрационные** вопросы, не готовая редакционная библиотека.
- `js/library.js` — генерация, печать, локальное сохранение.
- `js/home.js`, `js/common.js` — переключение поля, мобильное меню.
- `assets/logo.webp` — логотип, вырезанный из предоставленной наклейки на коробку (без изменения рисунка).
- `assets/villain_*.webp` — оригинальные предоставленные изображения четырёх злодеев с прозрачностью.
- `assets/board.webp`, `assets/board_alternative.webp` — два предоставленных макета поля.

## До публичного запуска

1. Настроить отдельные авторизованные аккаунты преподавателей, чтобы личные вопросы были действительно приватными.
2. Подключить PostgreSQL/Supabase с правами доступа (RLS), как ранее выбрано для проекта.
3. Сделать проверку постоянного пароля с игрового поля **на сервере**. Код DEMO не защищает ничего.
4. Настроить проверку и публикацию общедоступных пользовательских материалов без автоматического попадания в основную библиотеку, возможность удалить/пожаловаться.
5. Заменить примеры на проверенную редакционную базу вопросов и карточки маркетплейсов на реальные ссылки.
6. Проверить актуальную версию правил, финальный макет поля и ссылку из QR-кода. Исходный PDF с данными автора не публикуется автоматически.

GitHub Pages можно использовать для предварительного просмотра интерфейса, но **не** для хранения закрытой базы или логики авторизации. Вся секретная логика должна жить в Supabase/на сервере.
